# MoviePick 리서치 문서 08 — Playwright 여정 검증

- 프로젝트: MoviePick
- 역할: UX Usability Tester
- 단계: 리서치 문서 08. 4단계 사용자 여정의 화면 검증
- 작성일: 2026-11-21
- 상태: 로그아웃 상태 검증 완료. 로그인 후 저장 성공 경로는 미실행
- 서비스: https://moviepick-web.vercel.app/
- 기준 계획: [research/07_journey_plan.md](07_journey_plan.md)
- 도구: Playwright MCP
- 화면 증거: [research/08_screenshots](08_screenshots)

이 문서는 자동화로 연 화면, 그 화면의 문구, 클릭 후 바뀐 DOM, 콘솔에 남은 HTTP 상태, 상세 요청의 응답 본문을 적는다. 페르소나의 감정, 확신, 숙련도는 적지 않는다. 문서 07의 행동 B1–B8은 이번 테스트의 대본이 아니다. 그 행동이 이 화면에서 가능한지만 대조한다.

## 1. 문장을 구분하는 규칙

| 표기 | 의미 |
| --- | --- |
| 화면에서 확인 | 접근성 트리, 보이는 문구, 스크린샷에 있던 내용 |
| 응답에서 확인 | 브라우저가 받은 HTTP 상태 또는 응답 본문. 화면에 그려졌다는 뜻이 아니다 |
| 테스트 조건 | 테스터가 브라우저에 넣은 값. 서비스가 보여 준 이용 상황이 아니다 |
| 추정 | 화면과 응답에 이유가 없는 해석. 문제의 원인으로 확정하지 않는다 |
| 미실행 | 계정 생성 금지 때문에, 또는 화면 밖 기능이라 이번 세션에서 하지 않은 조작 |

## 2. 테스트 조건

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 주소 | https://moviepick-web.vercel.app/ | 화면에서 확인. 제목은 MoviePick |
| 뷰포트 | 1440×900 | 테스트 조건. 접속 전에 지정했다 |
| 시각 | 2026-11-21 16:22–16:26 KST | 테스트 조건 |
| 로그인 | 하지 않음 | 화면에서 확인. 이메일과 비밀번호는 비어 있었다 |
| 계정 생성 | 하지 않음 | 회원가입 버튼을 빈 값으로 한 번 눌렀고, 서버가 거절했다. 섹션 3.4 |
| 저장소 | `localStorage` 키 0개, `sessionStorage` 키 0개 | 저장 클릭 뒤에 확인 |

문서 07의 노트북, 혼자, 토요일 밤은 이번 세션의 관찰 값이 아니다.

## 3. 단계별 기록

### 3.1 영화 탐색

목적 대조: 문서 07의 1단계는 제목 없이 장르·분위기 목록을 여는 행동이다.

한 일: 홈을 열었다. 헤더, 영화 카드, 버튼, `nav` 요소를 세었다.

영화관 찾기에는 `수원 영화관`이 입력된 채로 있었고, 반경 기본값은 5km였다. 장소 검색과 내 위치 찾기는 누르지 않았다.

제목 `🎬 MoviePick`을 나중에 다시 누르자 검색어가 지워지고, 상태 문구가 `인기 영화를 살펴보세요.`로 돌아오고, 카드가 19개 다시 보였다.

이 단계에서 문서 07의 B1, 장르나 분위기 목록을 여는 조작은 해당 컨트롤이 화면에 없어 수행하지 못했다.

### 3.3 상세 정보 확인

한 일: 검색 결과에서 `기생충`의 `상세`를 눌렀다. 이어서 인기 목록으로 돌아온 뒤 `오디세이`의 `상세`를 눌러 위치를 재고, `상세 닫기`를 눌렀다.

화면 증거: [03_detail_parasite.png](08_screenshots/03_detail_parasite.png), [08_detail_below_grid.png](08_screenshots/08_detail_below_grid.png)

`기생충` 상세에서 화면에 있던 내용:

- 같은 주소. 새 경로로 바뀌지 않았다.
- 결과 카드 아래에 제목 `기생충`, 줄거리 문단, `개봉일: 2019-05-30 / 평점: 8.5`, 버튼 `상세 닫기`
- 상세 블록 안의 장르, 예고편, 러닝타임, 유사 작품, 감독, 출연, 재생 버튼은 본문에 없었다.
- 상태 문구: `영화 상세는 표시되지만 클릭 저장 실패: MySQL 저장 실패: 2005 (HY000): Unknown MySQL server host 'mysql-35c1ab15-tcocs-f176.j.aivencloud.com' (-2)`

응답에서 확인한 같은 클릭:

| 요청 | 결과 |
| --- | --- |
| `GET https://moviepick-api.onrender.com/movies/496243` | 200 |
| `POST https://moviepick-api.onrender.com/events/click` | 503 |

`496243` 응답 본문에는 화면에 없는 값이 있었다.

| 응답 필드 | 값 | 화면 |
| --- | --- | --- |
| genres | 코미디, 스릴러, 드라마 | 상세 블록에 장르 문구 없음 |
| runtime | 131 | 상세 블록에 러닝타임 문구 없음 |
| tagline | 행복은 나눌수록 커지잖아요. | 상세 블록에 없음 |
| vote_average | 8.489 | 화면 평점은 8.5 |
| release_date | 2019-05-30 | `개봉일: 2019-05-30`로 표시 |
| overview | 화면에 보인 줄거리와 같은 문단 | 표시됨 |
| video | false. `videos` 키는 이 본문에 없음 | 상세 블록에 iframe 0, video 0 |

`오디세이` 상세도 줄거리, `개봉일: 2026-07-15 / 평점: 8.0`, `상세 닫기`만 있었다. 그 블록의 iframe, video, img는 0개였다.

위치 측정. 인기 목록 19장에서 첫 카드 `상세`를 누른 직후:

| 측정 | 값 |
| --- | --- |
| 뷰포트 높이 | 900 |
| scrollY | 208 |
| 상세 제목 `오디세이`의 viewport top | 1683 |
| `상세 닫기`의 viewport top | 1839 |
| 제목이 보이는 영역 안인가 | 아니오 |

상세 블록은 카드 19개의 아래에 붙었다. 제목이 보이도록 직접 스크롤한 뒤에야 [08_detail_below_grid.png](08_screenshots/08_detail_below_grid.png)를 찍었다. `기생충` 4건 결과에서의 같은 좌표는 재지 않았다.

`상세 닫기` 후 `오디세이` 제목과 닫기 버튼은 DOM에서 사라졌다. 카드 19개는 남았다. 상태 문구는 MySQL 호스트 오류 그대로였다.

개봉연도라는 라벨은 없었다. 화면에 있던 라벨은 `개봉일`과 전체 날짜다. 장르는 이 상세 응답에는 있었고 화면에는 없었다. 평점은 카드와 상세 한 줄에 있었다.

### 3.4 관심 영화 저장

한 일: 로그인하지 않은 상태에서 `기생충` 카드의 `♡ 저장`을 눌렀다. 이어서 비어 있는 회원가입과 로그인을 눌러 저장이 막힌 이유를 보았다. 이메일과 비밀번호는 넣지 않았다.

화면 증거: [04_save_logged_out.png](08_screenshots/04_save_logged_out.png), [04b_login_required.png](08_screenshots/04b_login_required.png), [05_auth_empty.png](08_screenshots/05_auth_empty.png)

| 조작 | 화면 | 응답 |
| --- | --- | --- |
| `♡ 저장` | 상태 `즐겨찾기를 사용하려면 로그인하세요.` 즐겨찾기는 `내 즐겨찾기 (0)`, 안내 문구 유지 | 이 클릭으로 즐겨찾기 건수가 늘지 않음 |
| 저장 직후 저장소 | `localStorage` 0키, `sessionStorage` 0키 | 화면 밖 저장도 확인되지 않음 |
| 빈 `회원가입` | 상태 `Anonymous sign-ins are disabled` | `POST .../auth/v1/signup` 422. 본문 `anonymous_provider_disabled` |
| 빈 `로그인` | 상태 `missing email or phone` | `POST .../auth/v1/token?grant_type=password` 400 |

이메일 입력의 `required`는 false, 비밀번호 입력의 `required`는 false, `minLength`는 -1이었다. 두 입력 모두 form 요소 안에 있지 않았다. 빈 값인데도 버튼이 인증 요청을 보냈다.

상세 블록 안에는 저장 버튼이 없었다. 저장 버튼은 카드에 있다. 이유를 적는 입력칸, textarea, 메모 라벨은 이 화면에서 찾지 못했다.

저장한 영화가 목록에 나타나는지는 확인하지 못했다. 로그인된 세션이 없었고, 테스트 계정을 새로 만들지 않았다.

## 4. 같은 세션에서 추가로 누른 것

문서 07의 네 단계 밖에, 화면에 있던 검색과 통계가 어떻게 끝나는지 보았다.

### 4.1 검색창에 `드라마`

장르 목록 메뉴가 없어, 있는 검색창에 `드라마`를 넣고 Enter를 눌렀다. 장르 목록을 연 조작이 아니다.

화면 증거: [06_search_drama.png](08_screenshots/06_search_drama.png)

| 확인한 것 | 값 | 구분 |
| --- | --- | --- |
| 상태 | `검색 완료` | 화면에서 확인 |
| 화면 카드 | 20개 | 화면에서 확인 |
| 응답 | `GET /movies/search?q=드라마` 200. `page` 1, `total_results` 32, `total_pages` 2, `results` 20개 | 응답에서 확인 |
| 화면의 페이지 이동 | 다음 페이지 버튼 없음 | 화면에서 확인 |
| 제목과 개요에 `드라마`가 없는 결과 | 우리가 계절이라면, 한 여름의 꿈, 슬로우 | 응답에서 확인. 화면에 그 이유가 없음 |
| 장르 이름 | 응답의 `genre_ids`는 숫자. 이름 필드는 이 검색 결과 항목에 없음 | 응답에서 확인 |

20개 중 제목이 문장 형태인 항목이 화면에 있었다. `마약 밀매조직과의 싸움을 그린 범죄 드라마.`

숫자 `genre_ids`가 장르 이름과 같다는 해석은 추정이다. 화면은 그 숫자를 장르로 보여 주지 않았다.

### 4.2 맞지 않는 문자열

`zzzznotamovie999`를 입력하고 `검색` 버튼을 눌렀다. Enter가 아니라 버튼을 누른 경로다.

화면 증거: [07_search_empty.png](08_screenshots/07_search_empty.png)

상태 문구는 결과가 있을 때와 같은 `검색 완료`였다. 영화 카드는 0개였다. `영화 찾기` 구역의 본문은 `영화 찾기`와 `검색`뿐이었다. `결과가 없습니다` 같은 문구는 없었다.

### 4.3 통계 새로고침

`통계 새로고침`을 눌렀다. 상태 문구는 `MySQL 조회 실패: 2005 (HY000): Unknown MySQL server host 'mysql-35c1ab15-tcocs-f176.j.aivencloud.com' (-2)`로 바뀌었다. `POST`가 아니라 `GET https://moviepick-api.onrender.com/stats/popular`이 503이었다. 통계 목록에는 항목이 없었다. 그 아래 문구 `MongoDB에는 각 검색·클릭 이벤트가 개별 문서로 저장됩니다.`는 남아 있었다.

영화관 찾기와 내 위치 찾기는 누르지 않았다.

## 5. 문서 07 관찰 항목과의 대조

| 계획의 관찰 | 이번 화면에서 확인한 범위 |
| --- | --- |
| 1단계. 시작에 제목이 있는지 | 처음 연 검색창은 비어 있었다. placeholder 예시는 영화 제목 `기생충`, `인셉션`이다 |
| 1단계. 조건이 감정과 장르로 말해지는지 | 감정 조건 입력과 장르 목록은 화면에 없었다 |
| 1단계. 처음 화면이 장르·분위기 목록인지 | 상태 문구는 `인기 영화를 살펴보세요.` 카드 19개 |
| 1단계. 필터로 조건을 넣는지. H1 | 필터 컨트롤은 없었다. 제목 검색창은 있었다 |
| 2단계. 포스터로 후보를 거르는지 | 포스터는 카드에 있다. 자동화는 톤의 유사함을 판정하지 않는다 |

## 6. 발견한 문제

화면이 멈추거나, 안내가 없거나, 응답에 있던 정보가 상세에 나오지 않은 항목이다. 문서 07의 가설을 요구사항으로 올린 것이 아니다.

1. 로그인 전 `♡ 저장`은 상태 문구로 막힌다. 즐겨찾기 건수는 0에서 바뀌지 않았다. 저장 결과가 목록에 보이는 경로는 이번 세션에서 끝까지 가지 못했다.
2. 빈 회원가입과 빈 로그인이 서버 요청을 보낸다. 화면에 나온 문구는 `Anonymous sign-ins are disabled`, `missing email or phone`이다. 입력 옆에 붙은 검증 문구는 없었다.
3. `상세`를 누르면 줄거리는 같은 페이지에 나타난다. 인기 목록 19장에서는 그 블록의 제목이 뷰포트 아래 1683px에 있어, 스크롤 전에는 보이지 않았다. 같은 클릭의 클릭 기록 요청은 503이고, 상태 문구에 MySQL 호스트 이름이 그대로 나왔다.
4. `기생충` 상세 응답에는 장르 이름과 러닝타임 131이 있었다. 상세 블록에는 줄거리, 개봉일, 평점, 닫기만 있었다. 예고와 유사 작품은 이 블록과 이 응답 본문에서 확인하지 못했다.
5. 검색이 0건이어도 상태 문구는 `검색 완료`다. 0건 안내 문구는 없었다.
6. `드라마` 검색 응답은 32건, 2페이지였다. 화면은 20장이고 다음 페이지 컨트롤이 없었다. 제목과 개요에 검색어가 없는 3건이 포함되었다. 화면은 그 셋이 포함된 이유를 적지 않는다.
7. `통계 새로고침`은 `GET /stats/popular` 503이다. 목록은 비어 있고, 상태 문구가 인기 목록 안내를 같은 자리의 MySQL 오류로 바꾼다.
8. 문서 07의 1단계 행동인 장르·분위기 목록 열기는, 그 메뉴가 이 홈에 없어 수행하지 못했다. 홈의 영화 탐색 컨트롤은 제목 검색창과 인기 카드 19장이다.
